# Единый хедер Juniors Bootcamp

На всех страницах портала используется один хедер с одинаковой навигацией, поиском и управлением темой. Визуальный и интерактивный эталон — [header-kit](../../inputs/header-kit.zip): `demo.html`, `header.css` и скриншоты в архиве. Ссылка на [Navigation Menu shadcn/ui на Base UI](https://ui.shadcn.com/docs/components/base/navigation-menu) задаёт основу для выпадающих меню; компонент добавляется в UI kit проекта. Текущий `Header` уже расположен в корневом `app/layout.tsx`, поэтому новое поведение охватывает главную, задания, документацию заданий, гайды и страницу тестирования.

## Навигация и внешний вид

Хедер повторяет размеры, типографику, цвета, состояния и отступы архива в светлой и тёмной теме. В обычном режиме контейнер имеет ширину до 1280 px, на страницах документации заданий — до 1440 px, как в широком состоянии макета. Состав и порядок на десктопе: логотип `jb`, «Задания», «Документация», «Тестирование», «Open source», поиск, GitHub, переключение темы. Подготовленный в макете пункт «Войти» остаётся скрытым до появления входа в проекте. Хедер использует действующие адреса портала: «Тестирование» ведёт на `/qa`, «Гайды» — на `/guides`, «Все задания» — на `/tasks`.

«Задания» открывает список в порядке макета: Магазин игр, Пиццерия, Каршеринг, Кинотеатр, Доставка еды. Для существующих заданий используются рабочие маршруты `/tasks/<id>`, 3D-эмодзи из архива, описания и выделение текущего задания. «Магазин игр» виден с пометкой о недоступности и без перехода, пока его страницы нет. «Документация» содержит Скиллы, Архитектуру и Гайды в порядке макета; первые два пункта остаются неактивными. «Open source» показывает карточку reactuse, остальные проекты и ссылку на GitHub по макету. Внешние ссылки открываются как внешние, без фиктивных адресов `#`.

Меню открываются кликом по триггеру, показывают состояние открытия, закрываются по Escape, при переходе и клике вне меню. Ссылки доступны с клавиатуры; у неактивных пунктов нет ложного перехода, их состояние понятно визуально и через `aria-disabled`. Текущая страница отмечается в навигации. Работа меню не зависит от раздела, на котором находится пользователь.

## Поиск по документации

Кнопка поиска в хедере открывает окно из архива кликом и сочетанием `⌘K` / `Ctrl+K` на любой странице. [Репозиторий reactuse](https://github.com/siberiacancode/reactuse) служит дополнительным ориентиром для поискового меню. Фокус переходит в поле поиска; Escape и клик по подложке закрывают окно, после закрытия фокус возвращается к вызвавшему элементу. Результаты доступны с клавиатуры: стрелки меняют выбор, Enter открывает выбранную страницу. Окно имеет состояния без запроса, загрузки, результатов и отсутствия совпадений. В пустом состоянии показываются недавние переходы из поиска, если они есть. В подвале располагаются название и логотип Algolia из макета; для использования её бесплатного тарифа логотип обязателен по [документации Fumadocs](https://www.fumadocs.dev/docs/headless/search/algolia).

Источником результатов служат реальные MDX страницы заданий из `content/tasks` через существующий `tasksSource` Fumadocs. Индекс включает заголовки, разделы и текст, обновляется при публикации контента и даёт переход к найденной странице или разделу. Поиск охватывает все MDX страницы заданий независимо от текущего уровня, стека и блокировки страницы; переход на закрытую страницу сохраняет существующее поведение этой страницы. Гайды и обычные страницы портала в индекс этой версии не входят. Демонстрационные результаты из `demo.html` в продукте не используются.

Интеграция Fumadocs с Algolia включает подготовку документов, синхронизацию индекса и клиентский поиск для собственного окна по эталону. Публичные ID приложения и ключ поиска отделены от закрытого ключа записи. Пользователь донастроит Algolia и передаст ключи сам; без них сборка и остальной хедер должны работать, а поиск не должен показывать вымышленные результаты или выдавать пустой индекс за успешный ответ. После настройки ключей поиск выдаёт реальные результаты без изменения интерфейса.

## Адаптивность и взаимодействия

До 1100 px поле поиска превращается в круглую кнопку. До 860 px основная навигация, GitHub и «Войти» скрыты; остаются логотип, поиск, тема и бургер. Бургер открывает лист под хедером с группами заданий и документации, ссылками «Все задания», «Тестирование», «Open source» и теми же неактивными пунктами, что на десктопе. Лист повторяет геометрию архива, прокручивается при нехватке высоты, закрывается после перехода, по Escape и клику вне его. Переключатель темы сохраняет действующее поведение проекта на любой странице и меняет оформление хедера, меню и поиска без потери контраста.

## Проверка

- На главной, странице задания, странице MDX документации, в гайдах и на `/qa` отображаются одинаковые пункты и поведение хедера; документация использует широкий контейнер.
- Десктопное и мобильное состояния сверены со скриншотами архива при ширине 1440, 1024 и 390 px в обеих темах.
- Меню и поиск управляются мышью и клавиатурой, не теряют фокус при закрытии и не ведут на заглушки.
- После настройки Algolia запрос находит реальные заголовки и текст MDX, обновлённый контент попадает в индекс, а пустой запрос и отсутствие совпадений показывают состояния макета.
- При отсутствии ключей Algolia сборка проходит, поиск не показывает демонстрационные результаты; существующие метаданные страниц и работа Яндекс Метрики не нарушены.
