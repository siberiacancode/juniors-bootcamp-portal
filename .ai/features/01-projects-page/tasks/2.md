# Задача 2 · Добавить ручную синхронизацию каталога и скриншотов

## Описание

Разработчик запускает `sync-projects` и получает в портале готовый каталог со скриншотами из репозитория примеров. Результат хранится в Git и используется при сборке сайта.

## Реализация

Команда запускает TypeScript-скрипт через Bun. ZIP-архив основной ветки репозитория примеров запрашивается через GitHub REST API с `GITHUB_TOKEN` и Fetches-клиентом, заранее сгенерированным APICraft для `repos/download-zipball-archive` в `generated/api/github`. Скрипт распаковывает архив через `fflate` из devDependencies, разбирает корневой `projects.json` без отдельной schema-валидации, проверяет пути `preview`, переносит всю папку `images/` и готовит данные с локальными путями. Корень ZIP определяется по `projects.json`, поскольку его имя зависит от коммита. После проверки входных данных скрипт удаляет старое содержимое `public/projects/` и напрямую записывает новый набор, включая удаление устаревших файлов. Ошибка записи может оставить частично обновлённый набор; скрипт запускают повторно. Эти файлы коммитятся вручную. `.env.example` и инструкция локального запуска описывают токен и команду. `next build` и CI собирают сохранённый снимок без синхронизации.

## Тестирование

- При успешном запуске порядок записей сохраняется; все файлы из `images/` доступны по локальным путям, а файлы прежнего набора, которых больше нет в источнике, удалены.
- Без токена, при ошибке GitHub API, повреждённом ZIP, некорректном JSON или отсутствующем в архиве скриншоте команда завершается с ошибкой до удаления ранее сохранённого набора. Проверки соответствуют случаям «Каталог проектов» в `documentations/cases/проекты/страница-проектов.ts`.
- По коду страница использует сохранённый снимок без `GITHUB_TOKEN` и запросов к GitHub, а сборка и синхронизация не запускают повторную генерацию клиента. Проверка `next build` в этом цикле пропущена и не блокирует приёмку задачи.
