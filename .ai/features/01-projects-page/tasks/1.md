# Задача 1 · Создать каталог проектов и правила добавления в репозитории примеров

## Описание

В `juniors-bootcamp-examples` появляются корневые `projects.json` и `CONTRIBUTING.md`. Каталог содержит все четыре решения в текущем порядке README: два решения кинотеатра, аренду машин и доставку. Пустой `name` начальных записей допустим и не блокирует приёмку страницы `/projects`. Гайд объясняет подачу проекта через Issue и PR, в котором автор сам добавляет свою запись в конец каталога.

## Реализация

Каталог хранится массивом записей по контракту [спецификации](../spec.md): `username`, `name`, `task`, `framework`, `path` и при наличии `preview`. `path` указывает на копию решения в `examples/` репозитория примеров, например `examples/cinema/3`. Скриншоты хранятся в корневой папке `images/`, а `preview` задаётся путём от корня, например `images/project.png`. Порядок массива задаёт порядок карточек. Гайд требует от автора создать Issue с GitHub username, названием проекта, заданием, framework и ссылкой на исходный репозиторий; скриншот опционален. Затем автор отправляет PR с копией решения, при наличии скриншотом и своей записью **в конце массива** `projects.json`. Гайд содержит таблицу всех полей каталога. После проверки сопровождающий объединяет PR и закрывает Issue.

## Тестирование

- `projects.json` разбирается как JSON и содержит четыре записи в порядке README; `path` каждой начинается с `examples/` и ведёт к соответствующей копии решения.
- У каждой записи есть поля контракта; заданный `preview` ведёт в `images/` к существующему файлу. Пустой `name` начальных записей допускается.
- По `CONTRIBUTING.md` автор может определить обязательные и опциональные данные для Issue, поля `projects.json` и порядок подготовки PR. Для новых проектов название обязательно; запись ставится в конец массива, а шаги соответствуют сценарию `documentations/scenarios/проекты/добавление-проекта.puml`.
