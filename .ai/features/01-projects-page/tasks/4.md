# Задача 4 · Добавить фильтрацию проектов через URL

## Описание

Посетитель фильтрует галерею по заданию и framework, может открыть ссылку с выбранными условиями и сбросить фильтры, если совпадений нет. Карточки сохраняют порядок исходного каталога.

## Реализация

Клиентская часть страницы получает сохранённый каталог и управляет параметрами `task` и `framework` через существующий `nuqs` и контролы выбора проекта. Фильтры применяются к локальным данным через `AND`. Начальные значения «Все задания» и «Любой стек» не записываются в URL. Парсеры принимают только значения из спецификации; неизвестное значение отображается как начальное без очистки адреса, а второй корректный параметр продолжает действовать. При отсутствии совпадений галерею заменяет пустое состояние; сброс возвращает оба начальных значения и удаляет оба параметра из URL.

После согласия на аналитику выбор неначального задания отправляет `project_task_filter_click` с `task`, выбор неначального framework — `project_framework_filter_click` с `framework`. Возврат к начальному значению, сброс и восстановление из URL событий не отправляют.

## Тестирование

- Оба фильтра содержат установленные значения и по отдельности оставляют только подходящие проекты; совместно применяются через `AND` без изменения порядка карточек.
- `?task=…&framework=…` восстанавливает выбор после повторного открытия. Неизвестное значение показывает начальное состояние, остаётся в URL и не мешает другому корректному фильтру.
- При сочетании без совпадений показаны пустое состояние и сброс; после сброса видны все проекты, а `task` и `framework` отсутствуют в URL.
- Метрика получает согласованные цели и параметры только для выбора неначальных значений после согласия. Проверки фильтрации соотносятся с `documentations/cases/проекты/фильтрация-проектов.ts`.
