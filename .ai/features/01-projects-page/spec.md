# Проекты учеников

На странице `/projects` собраны решения учеников по заданиям Juniors Bootcamp. Посетитель может сравнить реализации, отфильтровать их по заданию и framework, открыть код и узнать, как добавить собственный проект. Внешний вид страницы задают приложенные desktop- и mobile-макеты.

## Галерея проектов

Страница начинается заголовком «Проекты», описанием, двумя фильтрами и кнопкой «Добавить свой проект». Ниже расположена masonry-галерея, а завершает страницу баннер «Сделал задание? Покажи всем» с кнопкой «Отправить проект».

На широком экране галерея состоит из трёх колонок, на мобильном — из одной. Промежуточная раскладка не допускает горизонтального скролла и сохраняет порядок проектов из источника данных. Светлая и тёмная темы используют существующие семантические токены; отдельная палитра для страницы не создаётся. Страница разделена на HeroSection, GallerySection и SubfooterSection. Маскот в костюме Индианы Джонса хранится в `public/illustrations/mascot/indiana-jones.webp`, а предоставленная текстура баннера — в `public/images/textures/projects-subfooter.svg`.

Для `/projects` задаются собственные русскоязычные title и description. Глобальный `noindex, nofollow` удаляется из [корневого layout](../../../app/layout.tsx), открывая сайт для индексации, а существующие Open Graph-настройки сохраняются. Header и его навигация остаются без изменений.

## Фильтрация

Фильтр заданий предлагает доставку, аренду машин, кинотеатр, пиццерию и магазин игр, а также начальное значение «Все задания». Фильтр framework предлагает React, Next, Vue, Nuxt и Angular и начальное значение «Любой стек».

Выбранные условия объединяются через `AND`, сохраняются через уже подключённый `nuqs` в query-параметрах `task` и `framework` и восстанавливаются при повторном открытии URL. Начальные значения не записываются в URL. Неизвестное значение параметра отображается как начальное, но остаётся в адресе до изменения этого параметра; другой корректный фильтр продолжает действовать. Если совпадений нет, вместо галереи выводится пустое состояние с действием сброса фильтров. Сброс возвращает оба фильтра к начальным значениям и удаляет их параметры из URL. Фильтрация работает с локальными данными без запросов к GitHub.

После согласия пользователя выбор неначального значения задания фиксируется через текущую Yandex Metrica целью `project_task_filter_click` с параметром `task`, а выбор неначального framework — целью `project_framework_filter_click` с параметром `framework`. Возврат к начальному значению, сброс фильтров и восстановление из URL событий не отправляют.

## Карточка проекта

Карточка показывает `@username`, название проекта и иконку framework. Если `name` у начального проекта пустой, вместо него показывается название задания. Если передан скриншот, он отображается в верхней части с осмысленным `alt`; без скриншота карточка остаётся компактной и не содержит пустой заглушки.

Иконка GitHub открывает копию решения в [juniors-bootcamp-examples](https://github.com/siberiacancode/juniors-bootcamp-examples), адрес которой формируется из поля `path`. Сама карточка не кликабельна. Ссылка на код открывается в новой вкладке, доступна с клавиатуры, имеет понятное название и безопасные атрибуты внешней ссылки.

После согласия пользователя переход в репозиторий фиксируется в Yandex Metrica с параметрами `username` и `task`.

## Каталог проектов

Источник галереи — корневой `projects.json` репозитория `juniors-bootcamp-examples`. Порядок записей в массиве определяет порядок карточек.

| Поле        | Тип                                            | Назначение                                                            |
| ----------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| `username`  | `string`                                       | Username автора                                                       |
| `name`      | `string`                                       | Название проекта; обязательно для новых записей                       |
| `task`      | `delivery \| cars \| cinema \| pizza \| games` | Задание                                                               |
| `framework` | `react \| next \| vue \| nuxt \| angular`      | Framework проекта                                                     |
| `path`      | `string`                                       | Путь к копии проекта в `examples/` репозитория примеров               |
| `preview`   | `string?`                                      | Опциональный путь к скриншоту относительно корня репозитория примеров |

Скриншоты репозитория примеров размещаются в корневой папке `images/`; значение `preview` начинается с `images/`. Для четырёх начальных решений пустой `name` допустим на текущем этапе и не блокирует приёмку страницы. Для новых проектов название обязательно. Корректность полей контролируется в репозитории примеров, поэтому портал не выполняет отдельную schema-валидацию. Синтаксически некорректный JSON остаётся ошибкой синхронизации.

Каталог обновляется вручную командой `sync-projects`: TypeScript-скрипт, запускаемый через Bun, получает ZIP-архив основной ветки репозитория примеров через GitHub REST API. Для запроса используется Fetches-клиент, заранее сгенерированный APICraft для операции `repos/download-zipball-archive` и сохранённый в `generated/api/github`; повторная генерация клиента не входит в обычную сборку или синхронизацию. Архив распаковывается библиотекой `fflate` из devDependencies. Для команды обязателен `GITHUB_TOKEN`, описанный в `.env.example`.

Скрипт находит в архиве корневой `projects.json`, проверяет пути `preview`, переносит всю папку `images/` и готовит каталог с локальными путями. Корневая папка ZIP определяется по `projects.json`, поскольку её имя зависит от коммита. После проверки архива, JSON и наличия указанных скриншотов он удаляет старое содержимое `public/projects/` и напрямую записывает новый набор файлов, который затем хранится в Git. Отсутствие токена, ошибка GitHub API, повреждённый ZIP, некорректный JSON или отсутствие указанного скриншота останавливают `sync-projects` до удаления прежнего набора. Ошибка записи файлов может оставить частично обновлённый каталог; в этом случае команду запускают повторно. `next build`, CI и runtime используют сохранённый снимок без запросов к GitHub и без `GITHUB_TOKEN`; для локальной разработки используется тот же снимок, который обновляется командой `sync-projects`, без отдельных моков.

## Добавление проекта

Обе CTA страницы ведут на `CONTRIBUTING.md` репозитория примеров. Гайд объясняет, как создать Issue и передать `username`, название, задание, framework, ссылку на исходный репозиторий и, при наличии, скриншот. Затем автор открывает PR: добавляет копию решения в `examples/`, при наличии скриншот в `images/` и собственную запись **в конец массива** `projects.json`. Гайд содержит таблицу полей каталога. Опциональный путь к скриншоту называется `preview`.

После проверки сопровождающий объединяет PR и закрывает Issue. Поэтому опубликованная карточка всегда ссылается на копию в репозитории примеров, а не на исходный репозиторий ученика.

Переход к гайду фиксируется после согласия пользователя с параметром размещения CTA: `gallery` или `subfooter`.

## Общий Footer

Текущий [Footer](../../../app/_components/layout/Footer/Footer.tsx) заменяется для всего сайта вариантом из макета. Он содержит wordmark `juniorsbootcamp`, описание, кнопку связи, социальные ссылки, колонки «Направления» и «Opensource siberiacancode», разделитель, copyright с автоматически подставляемым текущим годом и подпись об авторе и исходном коде. В «Направлениях» доступны `/tasks`, `/guides`, `/qa` и `/projects`, при этом Header остаётся без изменений. Ссылки используют общие константы, основные тексты — переводы проекта. Английская подпись об авторе и исходном коде остаётся текстом в компоненте.

На широком экране блоки располагаются горизонтально, на мобильном последовательно переходят в одну колонку. Footer использует общие цветовые токены в обеих темах, а все его ссылки доступны с клавиатуры и имеют понятные названия.

## Проверка

- `sync-projects` завершается ошибкой отдельно для отсутствующего токена, ошибки GitHub API, некорректного JSON и недоступного указанного скриншота, сохраняя прежний набор файлов.
- Страница использует сохранённый в Git снимок без токена и без запросов к GitHub; проверка `next build` в этом цикле пропущена и не блокирует приёмку.
- Карточки корректно отображаются с опциональным скриншотом и без него; пустой `name` начальных проектов заменяется названием задания.
- Query-параметры восстанавливают оба фильтра, включая неизвестные значения и результат без совпадений.
- Галерея и Footer соответствуют desktop- и mobile-макетам в обеих темах, а Header не изменяется.
- В готовой странице нет runtime-запросов к GitHub, глобального `noindex` и недоступных с клавиатуры ссылок.
