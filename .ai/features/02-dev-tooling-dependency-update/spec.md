# Обновление зависимостей и инструментов разработки

Обновить зависимости Juniors Bootcamp Portal, перейти с Yarn на pnpm и заменить прежнюю связку Husky, nano-staged и Prettier на общие конфигурации Siberia Can Code для Lefthook и Oxfmt. После перехода локальная разработка, коммиты и сборка используют один `pnpm-lock.yaml`.

## Зависимости и сборка

Обновить прямые зависимости из `dependencies` и `devDependencies` до актуальных стабильных версий, включая новые major-версии там, где они доступны. Добавить `@siberiacancode/lefthook` и `@siberiacancode/oxfmt` с необходимыми им исполняемыми пакетами. Удалить `@siberiacancode/prettier`, `husky` и `nano-staged`, а также прямой `clsx`, если после замены `cn` он больше не используется кодом приложения. `tailwind-merge` оставить. Зафиксировать согласованный набор версий в `package.json` и `pnpm-lock.yaml`, удалить `yarn.lock`. Локальная разработка и сборка используют pnpm 11 без поля `packageManager` в `package.json`.

В корне появляется `pnpm-workspace.yaml` по образцу [reactuse](https://github.com/siberiacancode/reactuse/blob/main/pnpm-workspace.yaml). Портал остаётся одним пакетом, поэтому шаблон `packages/*` из монорепозитория не копируется. В workspace-файле настраиваются применимые к порталу `publicHoistPattern`, `allowBuilds` и исключения `minimumReleaseAgeExclude` для зависимостей, которым они действительно нужны; записи для пакетов reactuse, не используемых порталом, не переносятся. Настройки позволяют устанавливать Lefthook, Oxfmt и зависимости сборки без ручных подтверждений и случайных различий между машинами. Неактуальные Yarn-записи удаляются также из `.gitignore`. Команды проекта и инструкции по запуску используют pnpm; Bun остаётся средой выполнения скрипта `sync-projects`.

Обновление считается завершённым после успешной установки `pnpm install --frozen-lockfile`, проверки типов и сборки Next.js. Контейнерная сборка через текущий Dockerfile тоже должна проходить: до установки копируются `package.json`, `pnpm-lock.yaml` и `pnpm-workspace.yaml`, а установка зависимостей, версия Node и отдельно закреплённый TypeScript приводятся в соответствие с обновлённым набором пакетов. Если обновление major-версии требует изменения кода или конфигурации, такое изменение входит в эту фичу и проверяется сборкой. Jenkins продолжает собирать и публиковать тот же Docker-образ.

## Форматирование и Git-хуки

Для Oxfmt использовать общий конфиг `@siberiacancode/oxfmt`. Команда `format` и составная команда `pretty` запускают Oxfmt вместо Prettier; `lint` продолжает использовать существующую конфигурацию ESLint. Правила исключения из `.prettierignore` переносятся в конфигурацию Oxfmt, после чего `.prettierignore` и `.prettierrc.mjs` удаляются. Форматирование охватывает исходники и используемые проектом файлы JSON, CSS, Markdown и MDX, не затрагивая генерируемые и служебные каталоги.

Git-хуки подключаются через опубликованный файл `@siberiacancode/lefthook/dist/lefthook.yml`. Его задание `pre-commit` с Prettier заменяется запуском Oxfmt по staged-файлам; проверка ESLint по staged-файлам сохраняется. Для файлов, которые меняют обе команды, выполнение организовано последовательно, а исправленные файлы попадают в коммит. Штатный `commit-msg` пресета добавляет префикс `<ветка> <emoji>` к сообщению и берёт emoji из `git config user.emoji`, а при отсутствии настройки использует 🧊. Файл `.emoji` и отдельная настройка 🌀 не нужны. Удаляются каталог `.husky`, конфигурация `nano-staged` и команды их установки; `prepare` устанавливает Lefthook. После миграции не остаётся прямых вызовов Prettier в командах проекта и Git-хуках.

## Объединение CSS-классов

Локальная функция `cn` продолжает применять `twMerge`, но для объединения входных значений использует `cn` из `@siberiacancode/reactuse` вместо `clsx`. Импорты компонентов из `@/lib/utils` и итоговое разрешение конфликтующих Tailwind-классов сохраняются. Удаляются импорты `ClassValue` и `clsx` из локальной утилиты. Внешний вид компонентов на узком и широком экранах, в светлой и тёмной темах после замены остаётся прежним.

## Проверка

- Установка зависимостей через `pnpm install --frozen-lockfile`, проверка типов, ESLint, Oxfmt и сборка Next.js проходят с обновлёнными пакетами.
- Dockerfile собирает приложение с тем же lockfile и workspace-настройками; запуск через `pnpm start` работает в собранном образе.
- `pre-commit` форматирует и проверяет staged-файлы через Oxfmt и ESLint без Prettier, Husky и nano-staged; `commit-msg` добавляет штатный префикс ровно один раз.
- Компоненты, использующие `cn`, сохраняют ожидаемые классы и отображение в основных адаптивных состояниях и обеих темах.
